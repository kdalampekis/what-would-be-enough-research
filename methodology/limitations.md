# Limitations and dual-use considerations

This document answers what the results of this project do not establish, which weaknesses of design, data and procedure a reader should weigh, and which misuses of the method are foreseeable. It consolidates Appendix A of the submission report ([paper/report.md](../paper/report.md)), which states the final claims, and Appendix A of the earlier extended report ([paper/extended_report.md](../paper/extended_report.md)), and adds items recorded elsewhere in the repository. Each item names its source. Amendments and deviations are listed in full in [protocol_amendments.md](protocol_amendments.md).

## 1. Scope of the tasks

- **Synthetic tasks.** "Every state is a small propositional problem in regular, machine-generated language. The results describe behaviour on these tasks and are not evidence about open-ended decisions with messy evidence" ([paper/report.md](../paper/report.md) Appendix A). The benchmark has 300 families and 2,282 states ([benchmark_design.md](benchmark_design.md)).
- **Static plans and guaranteed sufficiency only.** "A plan is chosen once, before any result is seen, and must settle the answer in every world the rules allow. Probabilities, noisy sources and step-by-step plans are outside this work" (same). "Real decisions often accept less than a guarantee and adapt as results arrive" ([paper/extended_report.md](../paper/extended_report.md) Appendix A.1). The planner module has an execution loop, but every reported result scores the static plan ([eop_architecture.md](eop_architecture.md) §5).
- **Costs are abstract units,** not time or money (both reports).

## 2. Models and runs

- **Four open-weight models, one provider, temperature 0, one answer per item.** "No closed frontier model was run and we have no estimate of run-to-run variation. The served model identifier is recorded for every response" ([paper/report.md](../paper/report.md) Appendix A). The proprietary models named in PROTOCOL.md §3 were not run ([docs/EXPERIMENT_INDEX.md](../docs/EXPERIMENT_INDEX.md) §1).
- **gemma is a separate condition.** It was run with its answer schema forced through a function tool; the key "+schema" is "a separate condition, not comparable to plain gemma" (EXPERIMENT_INDEX §1). Whether the backend constrains decoding "is not documented" ([src/msep/models/providers/adaption_provider.py](../src/msep/models/providers/adaption_provider.py)), and under the structured prompt gemma ignored the forced call in all 1,018 dev responses ([PREREG_EOP.md](../PREREG_EOP.md), Amendment 2).
- **Provider configuration taken from a pasted page.** Prices were "copied from the Adaption 'Models' docs page pasted by the user; the docs host was unreachable from the build environment", and the connector is marked as not verified against documentation ([configs/models.json](../configs/models.json), `_note_adaption`). Costs are reported in the provider's credits.
- **The run was interrupted.** "The laptop that drove the experiments slept once and lost its connection more than once." A provider outage stopped deepseek-v4-flash's held-out run from 2026-11-15 19:57 UTC; the run was paused by hand, resumed, and finished at 22:26 UTC with every call answered ([paper/extended_report.md](../paper/extended_report.md) Appendix A.1; [results/raw/network_guard.log](../results/raw/network_guard.log)).
- **Missing answers.** Seven gemma calls on held-out data failed all three registered attempts and count as wrong ([paper/report.md](../paper/report.md) Appendix B). On dev, one gemma Diagnosis-Controlled response is missing and is dropped from the denominator, against the all-attempted rule (EXPERIMENT_INDEX §5).

## 3. The mitigation (EOP)

- **EOP measures extraction, not planning.** "Its planner is exact. On the benchmark's own wording a parser with no model extracts every state, so a high EOP score there does not show that the model contributes anything; the rewording study tests that" ([paper/report.md](../paper/report.md) Appendix A). On held-out data the parser scores 1.00, and EOP scores 1.00, 1.00, 1.00 and 0.99 ([results/aggregate/final_test/RESULTS_TABLES.md](../results/aggregate/final_test/RESULTS_TABLES.md)).
- **The parser is the benchmark authors' own inverse.** "It was written by the benchmark authors as the inverse of the benchmark's own renderer, so its score on canonical text says nothing about other wordings" ([PREREG_FINAL.md](../PREREG_FINAL.md) §3).
- **The method tested on held-out data was chosen on development data.** The registered extraction prompt never showed the layout the reader requires; as registered, EOP failed on dev for three of four models (0.69, 0.65, 0.03 against native 0.96, 0.98, 0.96), and "the registered test (EOP better than native) was supported for gemma only" ([paper/report.md](../paper/report.md) Appendix B, Table B1). The held-out run is a prospective test of the amended method only.
- **EOP depends on the wording.** On reworded dev text the parser scores 0.00 on three of four rewordings; EOP holds for the two qwen models and breaks for deepseek (syntax 0.81) and gemma (syntax 0.05) ([results/aggregate/robust_dev/robust_report.md](../results/aggregate/robust_dev/robust_report.md)).
- **Silent errors.** On prose, 24 of 137 of gemma's extractions "are well-formed but are not the true state" ([paper/extended_report.md](../paper/extended_report.md) §4.3). In Study 3, one repair call raised gemma's exact-state rate from 0.21 to 0.78 and its accepted-but-wrong rate from 0.07 to 0.16 ([results/aggregate/repair/repair_report.md](../results/aggregate/repair/repair_report.md); [repair_supplement.json](../results/aggregate/repair/repair_supplement.json)).
- **A reader artifact in the rewording study.** Most of gemma's EOP-N answers there were written as message text instead of the forced call and were scored as empty. "Read as text, that prompt gives the exact state on 0.67 of the Study 3 items, so Figure 2 understates EOP-N for gemma" ([paper/report.md](../paper/report.md) §4.4). The rewording numbers were not re-scored.

## 4. The benchmark text: an artifact found by Study 1

The benchmark text was ambiguous about computed values. The header of the computational facts says the certified value "is not yet known", "while the known-values line can list one, and the action for it is usually still offered. A model that re-runs that computation is counted as over-intervening" ([paper/extended_report.md](../paper/extended_report.md) Appendix A.1). Of qwen3.5's 34 unnecessary plans on the 169 held-out states that one edit made sufficient, 21 "only re-obtain values the text lists as known" (exploratory; [paper/report.md](../paper/report.md) §4.2; [recertification.json](../results/aggregate/final_test/recertification/recertification.json)).

Follow-up Study 1 rendered 436 states from 60 fresh families in the original wording and in a clarified one ("its certified value is unknown unless it is listed under 'Known so far'"; [PREREG_FOLLOWUP.md](../PREREG_FOLLOWUP.md) §1). Acting on already-sufficient states fell from 0.14 to 0.03 [0.01, 0.05] for qwen3.5 and from 0.73 to 0.59 [0.51, 0.66] for gemma, both Holm p < 0.001; qwen3.8 stayed at 0.00 ([results/aggregate/followup/followup_report.md](../results/aggregate/followup/followup_report.md)). The report's reading: "for the strong models, most of the over-intervention we first measured was induced by our wording" ([paper/report.md](../paper/report.md) §4.2).

Consequences:

- The registered held-out test T-OI-1 (qwen3.5 0.20 [0.14, 0.27], gemma 0.72) "stands as measured, and its interpretation changes" ([paper/report.md](../paper/report.md) §5).
- The extended report's reading "what remains is stopping" is superseded ([paper/extended_report.md](../paper/extended_report.md), header note).
- The ambiguity is in every benchmark text used in the registered studies, including the held-out split. The benchmark was not re-issued in the clarified wording; the clarified wording exists only in Study 1 (retrospective interpretation, from the sources above).
- Study 1 is itself a follow-up registered after the held-out results were viewed (Section 5).

## 5. Evidence standing and procedure

- **The three follow-up studies were registered after the held-out results were viewed.** The held-out results were first viewed on 2026-11-15 at 20:23 UTC ([PREREG_FOLLOWUP.md](../PREREG_FOLLOWUP.md) §0). Studies 1 and 2 were committed at 21:03 UTC and Study 3 at 00:13 UTC on 2026-11-16 ([protocol_amendments.md](protocol_amendments.md)). "They use families no model had seen, and their protocols were frozen before their first response, but their questions were chosen with knowledge of the earlier results" ([paper/report.md](../paper/report.md) Appendix A). Study 3 is exploratory and has no significance test ([PREREG_REPAIR.md](../PREREG_REPAIR.md) §3). Studies 1 and 2 ran three models (not deepseek); Study 3 ran gemma and deepseek ([paper/report.md](../paper/report.md) Table 2).
- **The held-out results were first viewed before one run had finished,** during a provider outage, under a rule committed beforehand. Every held-out number reported is from the complete data; between the two analyses only deepseek's rows changed (native 0.73, then 0.98) ([paper/report.md](../paper/report.md) Appendix B; [results/aggregate/final_test/INTERIM_NOTE.md](../results/aggregate/final_test/INTERIM_NOTE.md)). This departs from PREREG_FINAL, which says the held-out results are analysed once, after every chain has finished (INTERIM_NOTE.md).
- **Most registered hypotheses were not supported.** H2 is not supported and is reversed for two models; H3 is supported for qwen3.8 only, with a small effect; H4a and H4b are not supported ([paper/report.md](../paper/report.md) §4.1). Development values of H2–H4 are exploratory (EXPERIMENT_INDEX §4.4).
- **Multiplicity.** "Holm correction within each family, α = 0.05; no correction across families" ([PREREG_FINAL.md](../PREREG_FINAL.md) §5).
- **Known defects in analysis outputs** (invalid E5 decoy fields on v3, mislabelled dev "confirmatory" p values, analyses planned but absent) are listed in EXPERIMENT_INDEX §5 and in [protocol_amendments.md](protocol_amendments.md) §5.
- **The rewordings are ours:** "four template-based kinds of change, audited by a language model on 24 texts, not by people" ([paper/report.md](../paper/report.md) Appendix A).
- **Not run:** "sequential plans, uncertain computation, further benchmark tiers, and a source-grounded extraction arm planned for Study 3" (same). The extended report also lists E10 as not run; E10 was later run as Study 2.

## 6. Dual-use and ethical considerations

From [paper/report.md](../paper/report.md) Appendix A, with the extended report's wording where it adds detail.

- **Selective disclosure.** "The method computes which missing facts would settle a question for the agent itself. Pointed at a person, the same idea (the smallest set of facts that fixes a conclusion) describes selective disclosure or selective evidence gathering. Our code has no model of another party's beliefs and would need a different formal model to do this, but the direction is foreseeable."
- **False confidence from an exact planner.** "'Already sufficient: stop' from a solver looks authoritative and is only as right as the extracted state. A wrong extraction gives a confident, wrong stop, and a check that was needed is skipped." Invalid extractions are counted as failures and well-formed wrong ones are reported separately. "A deployed version should show the extracted state before acting on it."
- **"Minimal" must not be read as "skip checks".** "A minimal plan is the cheapest among sufficient plans. Citing this work to justify fewer checks without a sufficiency guarantee would misuse it."
- **Benchmark scores can be over-read.** "A fixed parser with an exact planner solves the canonical benchmark. A high score on it is not a certificate of good epistemic behaviour."
- **Data and privacy.** "All items are synthetic. No personal data and no human participants were involved." The raw model responses are published as research evidence (commit `8e769b4`, 2026-11-14).
- **Resources.** "69,562 model calls over the sprint (65,120 answered, 830 truncated, 3,612 failed), costing 480 of the provider's credits."
